# Plot

**项目管理，化繁为简。**

Plot 是一个轻快的项目与任务管理工具。项目、任务、收件箱、定时任务和 AI agent
都在同一个工作区里——整个应用既能以单个可执行文件、Docker 镜像运行，也能部署到
Cloudflare Workers。

## Plot 是什么？

大多数任务管理工具只给两个选择：一种足够轻，但团队一大就撑不住；另一种功能齐全，
却要专人配置才能用。Plot 取中间：把小团队每天真正在做的那几件事做好、做快。

项目里放任务。任务有状态、优先级、一个负责人（人或 agent）、截止日期，需要拆分时
还可以有子任务。任务上发生的每件事都记录在任务本身，相关的人会在收件箱里收到通知，
正在看看板的人也会实时看到变化。

## 规划工作

*从一个项目开始，到一块谁都能一眼看懂的看板。*

- **项目 →** 卡片和表格两种布局，标签与标签筛选、侧边栏置顶，复制、重命名、归档和
  批量操作。每个项目的任务列表旁边都有概览面板：计数、状态与优先级分布、推进速度。
- **列表与看板 →** 两种布局共用同一套手动排序。在状态分组之间拖动任务，用筛选标签
  过滤，批量选择，右键快捷操作，无限滚动。
- **子任务 →** 最多三层拆分，进度以圆环汇总显示。
- **个人任务 →** 不是所有事都属于某个项目。任务可以独立存在（`T-<n>`），只对创建者、
  负责人和关注者可见。

## 推进工作

*一个任务，承载它的全部讨论。*

- **任务详情 →** 以侧栏、抽屉或全屏专注模式打开，到处都是同一个视图，活动记录会
  记下每一次修改。
- **全面支持 Markdown →** 描述和评论都是 Markdown，支持 `@成员` 和任务提及，以及附件
  （可直接粘贴上传）。
- **评论 →** 可以回复成串，也可以点赞。
- **命令面板与快捷键 →** 不离开键盘就能跳转到任何地方、执行任何操作。

## 掌握进展

*只收到和你有关的消息。*

- **收件箱 →** 被指派、状态变化、评论、提及、邀请和截止提醒都会通知到你。可以已读、
  稍后提醒、归档、筛选，或批量清空。
- **实时更新 →** 通过服务端推送（SSE）把变化推给每个打开的页面，并且只推给有权限
  看到的人。
- **浏览器通知 →** Plot 在后台时，新的收件箱消息会弹出桌面通知。
- **私信 →** 不用建任务，直接和同事聊。

## 引入 agent

*agent 是有边界的队友，而不是超级用户。*

- **有身份的 agent →** 每个 agent 归属于一个人，可以公开或私有，"使用"和"管理"
  分别授权。
- **天生受限 →** 把任务指派给 agent，或在评论里提及它。它以让它干活的那个人的令牌
  行事，并且只能在那个人指派或提及它的项目里活动。

## 按你的方式运行

*你的账号、你的数据、你的基础设施。*

- **账号 →** 本地密码、OIDC 单点登录，以及在首次 OIDC 登录时被认领的虚拟用户。会话、
  密码重置链接和带有效期的读 / 写访问令牌都在偏好设置里管理。
- **权限 →** 项目仅限邀请：所有者、直接成员和共享团队，项目角色为
  所有者 > 管理员 > 成员。全局级别分为普通用户、管理员（可读全部数据）和超级管理员。
- **团队与成员 →** 团队名册与邀请，成员页面展示动态、图表和私信，用户目录按权限可见。
- **设置与审计 →** 系统设置、成员与邀请管理、定时任务和审计日志，按级别展示。
- **定时任务 →** 内置调度器负责日志清理、审计日志保留、文件垃圾回收和截止提醒。
- **存储 →** 上传文件可以存本地磁盘、任意兼容 S3 的存储桶或 Cloudflare R2；也可以
  完全关闭上传，界面会自动隐藏相关入口。
- **随处可用 →** 中英双语，浅色 / 深色 / 跟随系统主题，桌面与移动端布局。

## 部署方式

同一套 API 代码，四种运行方式，应用代码无需任何改动。

| 方式 | 数据库 | 上传文件 |
| --- | --- | --- |
| Bun 直接运行源码 | SQLite 文件（libSQL）或远程 libSQL / Turso | 本地磁盘或 S3 |
| 单个可执行文件 | 同上，数据库迁移和前端都打包进可执行文件 | 本地磁盘或 S3 |
| Docker | 同上，以非 root 用户运行，数据放在卷里 | 本地磁盘或 S3 |
| Cloudflare Workers | D1，或远程 libSQL / Turso | R2 或 S3 |

在线体验部署在 Cloudflare Workers 上。

## 架构

```
                  浏览器（React SPA）
                        │
            HTTPS 上的 JSON  +  服务端推送（SSE）
                        │
          ┌─────────────┴─────────────┐
          │   Hono API  (OpenAPI 3.1)  │   Bun  ·  单文件  ·  Docker  ·  Workers
          └─────┬───────────────┬─────┘
                │               │
       ┌────────┴──────┐  ┌─────┴──────────────────┐
       │  Drizzle ORM  │  │  文件存储               │
       │  libSQL · D1  │  │  磁盘 · S3 · R2         │
       └───────────────┘  └────────────────────────┘
```

前端只通过从 API 自身的 OpenAPI 文档生成的类型来调用接口，两端的约定在构建时就会被
检查。应用代码只使用 Web API，各运行环境再注入自己的那部分实现——在 Cloudflare 上，
事件推送、调度器和限流由一个 Durable Object 承担。

| 层 | 技术栈 |
| --- | --- |
| 前端 | React 19、Vite 8、Tailwind CSS v4、shadcn/ui、TanStack Router + Query、Tiptap、Recharts、i18next |
| API | Hono，接口由 `@hono/zod-openapi` 定义、Scalar 生成文档，运行在 Bun 或 Cloudflare Workers 上 |
| 数据 | Drizzle ORM，底层为 libSQL（本地文件或 Turso）或 Cloudflare D1，支持全文搜索 |
| 实时 | 服务端推送（SSE）；在 Workers 上由 Durable Object 承载 |
| 语言 | 前后端全部使用 TypeScript |
